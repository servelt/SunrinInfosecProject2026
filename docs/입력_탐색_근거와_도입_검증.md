# 입력 탐색 수정의 근거와 적용 범위 (2026-10-29)

이 문서의 `if` 후보는 현재 `OperationSeed` **탐색·감사 단서**를 뜻한다. 2026-10-29 의미 동작 재설계 이후 분기별 Action 작업을 만드는 실행 정책은 사용하지 않는다. 현재 정책은 [의미기반_동작_재설계_근거.md](의미기반_동작_재설계_근거.md)에 기록했다.

이 문서는 논문 결과를 HarnessCreator의 성능 보증으로 취급하지 않는다. 먼저 원래 연구의 문제와 전제를 확인하고, 이 저장소에서 실제로 관찰한 실패에 대응하는 최소 변경만 기록한다.

## 이 코드에서 확인한 문제와 변경

1. 함수 16개는 사용자가 정한 분석 기준이 아니었다. `--context-functions`의 기본값을 `0`으로 바꿨다. `0`은 열린 함수가 중복되지 않는다는 조건하에서 제품 호출 그래프의 함수 수까지 필요한 소스를 계속 요청할 수 있다는 뜻이다. 사용자가 양의 작업 예산을 지정해 중단되면 `entries/continuations.jsonl`과 `input-surfaces/continuations.json`에 열린 함수와 다음 함수 ID를 기록한다. 이전 실행의 모델 호출 기록을 `--resume-from`에 주고 더 큰 예산을 지정하면 동일한 앞부분을 재사용한 뒤 다음 소스를 연다. 모델 입력에는 숫자 예산을 넣지 않아 예산 변경 자체가 기록 재사용을 깨지 않도록 했다. 단, 코드·모델·프롬프트가 달라지면 기록 재사용이 보장되지 않고 새 분석이 필요하다.
2. 초기 원본 실행의 8건 상한은 근거 없는 기본값이었다. 기본값 `0`으로 모든 **생성된 입력 사례**를 초기 시험 대상으로 두었다. `--max-initial-input-trials N`을 명시한 경우에만 제한한다. `runtime-trials.json`에는 아직 실행하지 않은 사례와 이유를 남긴다. 이 변경은 실행 비용을 늘릴 수 있으며, 시험한 사례의 정상성이나 목표 도달을 자동으로 증명하지 않는다.
3. 샘플이 없으면 만들어 넣던 기본 시험 바이트를 제거했다. 요청 파일이 없고 모델도 구체적인 입력을 제시하지 못하면 `no replayable sample` 의무를 남긴다. 모델이 제시한 바이트는 계속 `model_input_hypothesis`로 표시하고 원본 실행에서 별도 확인한다.
4. 함수 호출이 없다는 이유로 `if`를 버리던 규칙을 좁혔다. Entry 바이트에서 이어지는 소스 식별자가 조건에 들어가고 본문에 동작이 있으면 `POSSIBLE` **구문 단서**로 기록한다. 호출이 있는 `if`도 입력과의 연결이 자동으로 성립하지는 않는다. `read(fd, c->rbuf + c->rbytes, n)`에서는 실제 쓰기 대상인 `rbuf`만 추적하고 소유 객체 `c`와 오프셋 `rbytes`는 입력 값으로 취급하지 않는다. 한 줄에 여러 `if`가 있을 때 조건과 본문이 이웃 분기를 삼키지 않도록 파싱도 수정했다. 이후 의미 동작 재설계에서 이 구문 단서로 별도 Action 작업을 예약하던 경로를 기본 실행에서 제거했다.

## 도입 시 예상되는 손실과 확인 기준

- 제한을 기본으로 두지 않으므로 큰 제품에서는 모델 호출과 원본 시험 시간이 늘 수 있다. 중복 함수·더 열 수 없는 함수에서 멈추며, 필요하면 사용자가 명시적으로 작업 예산을 준다. 예산 도달은 `VERIFIED` 또는 `REJECTED`의 근거가 아니다.
- 직접 인자 전달만 추적하는 현 소스 흐름은 alias, callback, 공유 상태를 통한 전달을 완전히 잡지 못한다. 이런 경우를 `Action 없음`이라는 결론으로 사용하지 않고 미해결 의무로 보고한다. SVF의 가능한 간접 대상 역시 증명이 아니다.
- `if` 후보가 추가되므로 검토 비용과 오탐 후보가 늘 수 있다. 특히 과거의 분기 폭증은 잘못 포함된 backend 응답 Entry와 내부 분기 재확장이 함께 만든 결과였다. 이번 회귀 검사는 호출이 있는 내부 상태 분기와 한 줄의 이웃 분기까지 배제하는지 확인한다. 데이터 흐름을 놓친 진짜 입력 분기는 자동 작업 대신 미해결 의무로 남을 수 있으므로, 이는 임의의 C/C++ 프로그램에 대한 완전성 증명이 아니다.
- 실제 `/mnt/c/memcached` 소스를 정적 인덱싱한 점검에서는 함수 2,461개와 호출 관계 11,722개를 얻었고, `try_read_network`의 초기 Action 후보는 7개, `try_read_udp`는 0개였다. 이 수치는 이번 변경으로 무차별 분기 폭증이 일어나지 않았다는 좁은 확인일 뿐, 모든 요청 기능을 찾았다는 뜻은 아니다. 특히 `try_read_udp` 이후 경로처럼 직접 인자 전달만으로 이어지지 않는 흐름은 별도 의무로 남는다.
- GDB는 설정된 원본 실행에서 호출 순서를 관찰할 수 있지만, 다른 스레드나 요청을 구분하지 못하는 관찰만으로 `PROVEN_RUNTIME`을 부여하지 않는다. 원본 요청별 귀속 증명과 최종 하네스 검증은 여전히 별도의 조건이다.
